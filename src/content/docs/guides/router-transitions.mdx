## Two trees, one handoff

During navigation `@xzsv/router` holds **two** component trees mounted: the outgoing one and the incoming one. It computes an equality point (`eq`) — how many leading nodes (same component, same params) the two trees share. Everything at or before `eq` is the **persistent prefix**: same components, same DOM, and it never receives transition callbacks. Everything past it gets `enter` (on the incoming tree) or `leave` (on the outgoing tree).

The router waits for the promises your callbacks return — bounded by `timeoutMs` (default 1000) so a forgotten animation can't wedge navigation — then unmounts the outgoing tree. Layouts and pages that don't opt in simply don't animate.

That is the whole contract. The animation is plain CSS you write; the router only orchestrates the handoff.

## Opting a page in

```svelte
<section class='page' {@attach routeNode}>
	<!-- page content -->
</section>
```

`routeNode` registers the element under its tree-node id. On navigation the router collects registered elements and calls your functions:

```ts
enter: (el, info) => Promise<void>
leave: (el, info) => Promise<void>
// info: { depth, key, from, to, navigationId }
```

The `info` argument carries the from/to route identity, which is what direction-aware transitions are built on: forward navigations slide one way, back navigations the other.

## Why layouts never animate

The layout sits at the top of the tree and is identical across pages, so `eq` always includes it: no callbacks, no remount. Nav-tab highlights, unread badges, running timers, and playing audio survive every navigation because their DOM nodes are never touched. This is the structural guarantee that distinguishes the dual-tree model from swap-and-snapshot approaches: a persistent layout physically cannot flicker, because it never receives a callback.

## Details that took debugging to find

1. **Forced reflow** (`void el.offsetWidth`) between setting the start state and starting the transition — without it the browser coalesces both writes and nothing animates.
2. **`position: absolute` on the leaving element** — otherwise the incoming page renders below the outgoing one (both in flow) and the page visibly jumps. The parent needs `position: relative`.
3. **Resolve on `transitionend` _or_ a timer** — cancelled tabs, `prefers-reduced-motion`, and interrupted transitions all still finalize the navigation.

## Transitions and the View Transitions API

Same-document View Transitions are now in all three major engines, and router 0.3.0 ships an opt-in flag for them: set `viewTransition: true` in your `transitions` config and the tree swap is wrapped in `document.startViewTransition()`, with a plain instant swap where the API is missing. It composes with this model rather than replacing it: the View Transitions API captures page snapshots, while the dual-tree keeps shared layouts untouched — so `::view-transition-*` rules only ever see the part that actually changed.

## Chrome transitions, events, scroll (0.4.0)

The equality point has a blind spot: the HUD lives in the layout, which never animates — but sometimes the chrome itself must react (nav bar morphs, tab indicator slides). Register any element with `{@attach chromeNode}` — anywhere in the tree, no route context — and provide a `chrome` pair:

```ts
transitions: {
	chrome: {
		enter: (el, info) => { /* depth: -1 */ },
		leave: (el, info) => { /* same batch, same timeoutMs */ },
	},
}
```

Chrome callbacks join the same transition batch as route nodes and are never skipped by the equality point.

To observe navigation from outside your hooks, subscribe with `router.onNavigation(ev => …)`: every navigation streams `{ id, phase, from, to, params, keys, cause }` with `id` stable across the pipeline (it matches the `navigationId` on hook args and `RouteNodeInfo`), and `cause` telling you `initial`, `link`, `popstate`, or `programmatic`. Scroll became explicit too: the default no longer force-scrolls on back/forward, and `createRouter({ scroll: 'restore' })` saves per-entry offsets into `history.state.__xzsv` and restores them on popstate.
